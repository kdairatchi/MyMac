## 2. Writeup of last 72h

**"IDOR: private post comments can be read and written by any authenticated user"**
- Author: matteo · Platform: HackerOne (disclosed ~2026-11-23)
- URL: https://www.redpacketsecurity.com/hackerone-bugbounty-disclosure-idor-private-post-comments-can-be-read-and-written-by-any-authenticated-user-matteo/ (domain not reachable from this env)
- Target: web API
- Bug class: IDOR
- Aha: "Private" enforced at UI layer only. Comments API endpoint accepted any authenticated session's request against any object ID without validating ownership. Auth check stopped at the session, not at the resource.
- Hunt recipe:
  1. Create accounts A and B on target. Post private content as A, capture the comment/resource endpoint and object ID.
  2. Authenticated as B, replay `GET /api/comments/{A_object_id}` or `POST /api/comments` with A's resource ID.
  3. 200 with data = IDOR. Escalate severity by chaining: find a second endpoint that leaks object IDs (notification feed, search, activity log).
- Kill criterion: Server returns 403 with cross-user object ID under same authenticated session — object-level auth is enforced.
