- **What:** Seven CVEs patched in Firefox 150 / ESR 140.10 — two mitigation bypasses in Networking:Cookies (9.8), one uninitialized memory in WebCodecs (9.8), two privesc in Networking+Debugger (8.8), one mitigation bypass in DOM:Security (9.8), one privesc in WebRender (9.8).
- **Why it matters:** If any program ships Electron or embeds a WebView backed by Gecko — check the version. Cookie mitigation bypasses (CVE-2026-6760/6768) also worth variant-hunting in non-browser targets using same Gecko cookie logic.
- **Hunt signal:** `grep -r "firefox\|gecko\|electron" package.json` on Electron targets; check `User-Agent` to fingerprint browser stack. Pass for pure web app targets. [source] NVD · [inference] cookie mitigation bypass may affect Gecko-derived libs outside browser context.

### Intigriti: PostMessage Exploitation — Complete Guide
- **Date:** 2026-01-31 · **Source:** [intigriti.com](https://www.intigriti.com/researchers/blog/hacking-tools/exploiting-postmessage-vulnerabilities) · **Class:** technique
- **What:** Full walkthrough on postMessage origin validation bypass, wildcard `targetOrigin`, and handler exploitation for XSS/data exfil.
- **Why it matters:** postMessage is underscanned by automated tools — it needs JS execution to trigger and the origin check is often client-side logic, not header-enforced. High dupe rate on obvious patterns but origin mismatches in SPAs still find bounties.
- **Hunt signal:** `grep -r "addEventListener.*message\|postMessage" dist/ src/` + manually test `targetOrigin` of outbound messages. Focus on OAuth and payment widget iframes where data flows cross-origin. [source] Intigriti blog.

### PortSwigger: Unicode Overflow → Character Blocklist Bypass
- **Date:** 2025-01-28 · **Source:** [portswigger.net](https://portswigger.net/research/bypassing-character-blocklists-with-unicode-overflows) · **Class:** technique
- **What:** Certain Unicode codepoints overflow/normalize in ways that bypass WAF and app-level character blocklists — useful for injecting `<`, `>`, `'`, `"` equivalents after server-side normalization.
- **Why it matters:** Any WAF that blocks on byte patterns before Unicode normalization is vulnerable. Works against Cloudflare, Akamai, and custom regex filters that don't normalize input first.
- **Hunt signal:** Fuzz input fields with `<`, `﹤`, `﹤`, `＜` etc. — burp's Unicode fuzzer or `ffuf -w unicode-angles.txt`. Check if the stored/reflected output normalizes to `<`. Files into `Cheatsheets/waf-bypass.md`. [source] PortSwigger Research.
