What CAN Be Automated (per program — ALWAYS check policy)

Always-Allowed Automation

  • Subdomain enum: subfinder, assetfinder, amass — passive only
  • Cert transparency: crt.sh, censys
  • Wayback / GAU: historical URL pull
  • Tech-detect: httpx -tech-detect (single hit per host)
  • WAF probe: wafw00f (single hit per host)
  • DNS / WHOIS: standard lookups
  • OAST callback: interactsh listening passively
  • Static JS analysis: LinkFinder, SecretFinder offline on downloaded bundles

Conditionally-Allowed (READ POLICY)

  • Nuclei: Chaturbate ≤100 req/min OK · XVIDEOS BANS automation entirely · most others OK at low rate
  • Burp Active Scan: usually allowed on own accounts only · check rate limits
  • Brute force: Chaturbate explicitly allows ≤100 req/min on own accounts to test rate-limit · most ban it
  • Directory fuzzing (ffuf): usually OK at low rate, banned on some (XVIDEOS)
  • SQLi auto (sqlmap): rarely allowed; always read program + use lowest threads

Never Automate (always manual)

  • Auth flows (login brute / password reset)
  • Payment / billing / withdrawal endpoints
  • State-changing endpoints with real-world side effects
  • Cross-account testing (use your own accounts only, manual)
  • Anything on a target that says "no automation" (XVIDEOS)

kdairatchi-Style Hunt Footprint (not parroted public methodology)

Signature moves

  • Variant hunt over fresh hunt — read disclosed reports, find what's been fixed-locally-but-not-globally
  • Stack-drift exploitation — when an app runs Flask + Gin (smtp2go pattern), the newer language path skips middleware
  • Wayback-first recon — pull old URLs/JWTs out of archive.org before any live probe (smtp2go gave us 8 expired JWTs revealing schema)
  • Caido DB mining — never re-issue requests; mine the captured traffic for IDOR/auth/CORS/RPC patterns first
  • Cross-brand backend search — sister brands (Mobile Vikings + JIM, xvideos + xnxx, eero + Ring) often share auth backend
  • Honest park — if a finding can't be PoC'd today, it goes to LEAD column, not a soft report

Anti-patterns I avoid

  • No theoretical CORS (`could potentially exfiltrate`) — prove impact or kill
  • No public CVE direct submissions — race to dupe
  • No raw nuclei output — every nuclei hit gets manual confirmation
  • No Burp-only XSS — needs realistic victim browser context
  • No "X is sequential therefore IDOR" — needs cross-account read proof
  • No reports against unconfirmed scope — ASK the program for clarification

Where my style comes from

  • Stack-drift mindset: I look for the seams between layers (Flask↔Gin, Apache↔ALB, mobile↔web)
  • Memory-driven: every session writes to journal + auto-memory; future me reads past me's failures
  • Honest journal: closed-Dup is a real outcome to log, not hidden
  • Tool-builder, not tool-consumer: krait, hwaro, prowlrview are mine — I shape them around the bug classes I hunt
